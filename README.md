## Система разграничения прав доступа (RBAC)

В проекте реализована система контроля доступа на основе ролей.

### Структура таблиц

#### Таблица `users`
- `id` (PK) - идентификатор пользователя
- `name` - имя пользователя
- `surname` - фамилия пользователя
- `patronymics` - отчество пользователя
- `email` - email
- `hashed_password` - хеш пароля
- `is_active` - активен ли пользователь
- `is_superuser` - является ли суперюзером
- `created_at` - дата создания

#### Таблица `user_settings`
- `id` (PK) - идентификатор роли
- `users_id` (FK) - идентификатор юзера
- `can_see_users` - разрешен ли получение списка пользователей


### Матрица доступа

| Роль | Действия     | Условие                                             | Доступ |
|------|--------------|-----------------------------------------------------|--------|
| **admin** | все действия | Суперюзер                                           | Разрешен |
 | **user** | все кроме /update_user_settings (исключение "/") | Если администратор закрыл доступ к получению юзеров | Запрещен

### API для управления правами

| Метод  | Эндпоинт                       | Описание                                                                 |
|--------|--------------------------------|--------------------------------------------------------------------------|
| GET    | `/api/v1/users/`               | Получить список всех пользователей (если авторизован и не закрыт доступ) |
| POST   | `/api/v1/login`                | Войти в аккаунт                                                          |
| POST   | `/api/v1/logout`               | Выйти с аккаунта                                                         |
| GET    | `/api/v1/me`                   | Получить данные о себе (если авторизован)                                |
| POST   | `/api/v1/registration`         | Регистрация                                                              |
| POST   | `/api/v1/update_user_settings` | Отозвать разрешение на просмотр пользователей или наоборот               |
| PATCH  | `/api/v1/update`               | Обновить данные о себе                                                   |
| DELETE | `/api/v1/delete_account`       | Удалить аккаунт                                                          |


### Алгоритм проверки доступа

1. Из запроса извлекается токен и сверяется с токеном из Redis
2. Если токен отсутствует или невалиден → `401 Unauthorized`
3. По токену из redis определяется пользователь
4. Получаются роль пользователя
5. Получаются все разрешения из таблицы настройки
6. Проверяется наличие необходимого разрешения для ресурса/действия
7. Если разрешение есть → возвращается ресурс
8. Если разрешения нет → HTTPException

### Примеры

####  Неуспешный доступ (401)
```http
INFO:     127.0.0.1:64681 - "GET /api/v1/users/ HTTP/1.1" 401 Unauthorized
```


## Старт приложения

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Bulstray/TestEffectiveMobile.git
```

### 2. Установка зависимостей
```bash
uv sync
```

### 3. Настроить переменные окружения
Создать файл .env внутри fastapi-auth (можно скопировать данные из .env.template)
Обратить внимание, что совпадают название pg, логина и пароля

### 4. Применить миграции
```bash
alembic upgrade head
```
